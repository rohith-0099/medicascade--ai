## 1. Project Overview

**MediCascade AI** is a multi-layer clinical decision support system that processes patient medical PDFs through a 4-layer AI cascade pipeline, producing an annotated diagnostic report with evidence-based reasoning. It also includes a separate 3D brain tumor segmentation subsystem using nnU-Net.

**Core Philosophy**: Mimics a real hospital diagnostic workflow — intake → specialist consultation → evidence validation → annotated report. Every fact is traceable back to its source page and text span (full provenance).

**License**: All components are free and open-source. No paid APIs are required (Groq, OpenRouter, OpenFDA, PubMed NIH eUtils all have free tiers).

## 8. MRI 3D Tumor Segmentation Subsystem

### Model
- **nnU-Net v2** — self-configuring medical image segmentation framework
- **Weights**: BraTS 2021 challenge (Zenodo record 11582627), Apache 2.0 license
- **Size**: 1.1GB (5 folds × ~220MB each)
- **Architecture**: 3D UNet with 6 encoder/decoder levels

### Label Mapping (from dataset.json)
```
0 = background
1 = edema (peritumoral)
2 = nonenhancing / necrotic tumor core
3 = (empty — not used by this model)
4 = enhancing tumor
```

### Inference Pipeline
```
4 NIfTI uploads (T1, T1CE, T2, FLAIR)
  → nibabel load (float32, 3D)
  → Shape validation (all must match)
  → Spacing extraction from NIfTI header
  → np.stack([t1, t1ce, t2, flair]) → (4, D, H, W)
  → nnUNetPredictor.predict_single_npy_array()
  → Segmentation mask (D, H, W) with labels 0,1,2,4
```

### Mesh Generation Pipeline
```
Segmentation mask + raw FLAIR volume
  → Brain: marching cubes on raw FLAIR (downsampled 2x, Gaussian σ=1.5)
  → Tumors: marching cubes on smoothed binary masks (Gaussian σ=1.2)
  → Laplacian smoothing (brain: 15 iters, tumors: 8 iters)
  → Face decimation (brain: max 60k, tumors: max 50k)
  → Convert to Plotly Mesh3d format (x,y,z,i,j,k arrays)
```

### Performance Settings (optimized for RTX 3050 4GB)
- **Folds**: 1 (single fold, not 5-fold ensemble) — 5x speedup
- **Mirroring**: Disabled — 8x speedup
- **Net effect**: ~40x fewer forward passes (from 40 to 1)
- **Expected time**: ~1-2 minutes (was 10-15 minutes)

## 11. Frontend Architecture

### Main App (`App.jsx`)
- Single-page app with sidebar navigation
- Two view modes: **Clinical** (PDF diagnosis) and **MRI** (3D brain viewer)
- MriTumorView is lazy-loaded via `React.lazy()` + `Suspense`
- 14-stage animated thinking log simulates real pipeline progress
- Pipeline progress bar with 4 layers (L0 → L1 → L2 → L3)

### MRI Viewer (`MriTumorView.jsx`)
- Upload 4 NIfTI files (T1, T1CE, T2, FLAIR)
- Sends to `/api/mri/analyze` via FormData
- Renders Plotly Mesh3d with 4 layers: brain, necrotic, edema, enhancing
- Toggle layer visibility, adjust brain opacity (0-100%)
- Shows mesh geometry stats (vertex/face counts)
- Shows tumor volume stats (cm³, voxel counts)
- `useMemo` on plot traces to prevent unnecessary recomputation

### UI Theme
- Deep black background (#050b18) with cyan grid pattern
- Cyan neon accent (#00d4ff) + purple secondary (#7c3aed)
- Fonts: Space Grotesk (headings) + JetBrains Mono (code/labels)
- Dark glassmorphic cards (semi-transparent backgrounds, no backdrop-filter for performance)

### Build Optimization
- **Chunk splitting**: Plotly.js (4.8MB) in separate lazy chunk — main bundle only 159KB
- **No backdrop-filter**: Removed from all 9 CSS classes that had it (was causing GPU compositing lag)
- **Lazy loading**: MriTumorView only loads when user navigates to MRI view

**nnU-Net inference speedup** (`backend/mri/predictor.py`):
- Changed from 5-fold ensemble to single fold (fold_0) — 5x speedup
- Disabled test-time mirroring (8 orientations → 1) — 8x speedup
- Net: ~40x fewer forward passes, inference time ~1-2 min instead of 10-15 min

## 14. Key Design Decisions

1. **No external database** — SQLite is sufficient for single-server deployment and has zero setup
2. **Deterministic fallback at every layer** — if all APIs fail, heuristic rules still produce a diagnosis
3. **Full provenance** — every extracted fact tracks its source page and text span
4. **Free-tier only** — Groq, OpenRouter, PubMed, OpenFDA all have free tiers
5. **Single-fold nnU-Net** — trades ~1-2% accuracy for 40x inference speedup on consumer GPUs
6. **Raw FLAIR for brain mesh** — uses raw intensity (not z-normalized) for accurate brain isosurface
7. **Plotly over Three.js** — simpler integration, no GLB conversion, built-in camera controls
8. **No backdrop-filter** — glassmorphism visual effect was causing constant GPU compositing, removed for performance
9. **Payload truncation** — Layer 2 sends compact summaries to stay under Groq's 12k token limit
10. **Error sanitization** — raw API errors never reach the patient-facing PDF report
